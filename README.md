# AKM-бот

Telegram-агент для AKM Holdings с интеграцией Linko.
Два канала: **A** — автоответчик внутри рабочего аккаунта (Telegram Business),
**B** — обычный бот для групп сотрудников, каталога и корзины.

ТЗ: `tz-akm-bot.html`

## Запуск за пять минут

```bash
npm install
cp .env.example .env      # заполнить, см. ниже
npm run check             # проверка всех подключений
npm run seed              # демо-данные (пока Linko закрыт)
npm run dev               # запуск
```

`npm run check` проверяет базу, Linko и Telegram и говорит, чего не хватает.
Запускайте его после каждого изменения `.env`.

## Что вписать в `.env`

### 1. Бот — 2 минуты

1. В Telegram открыть **@BotFather** → `/newbot` → задать имя.
2. Скопировать токен в `BOT_TOKEN`.
3. **Обязательно** включить Business-режим, иначе канал A работать не будет:
   `/mybots` → выбрать бота → **Bot Settings** → **Secretary Mode** → включить.

   > В мае 2026 Telegram переименовал этот переключатель: раньше он назывался
   > **Business Mode**. Если в вашем клиенте старое название — это он же.

### 2. Группы сотрудников — 2 минуты

1. Создать группу «Бухгалтерия», добавить туда бота.
2. Написать в группе `/chatid` — бот ответит числом вида `-1001234567890`.
3. Вписать его в `ACCOUNTANT_CHAT_ID`. Так же для `FINANCE_CHAT_ID` и `MANAGER_CHAT_ID`.

### 3. Linko

```
LINKO_BASE_URL=https://sfademo.linko.uz
LINKO_TOKEN=<токен>
```

> **Сейчас блокер.** Демо-контур отвечает `403 External-api integration disabled` —
> внешний API выключен на стороне Linko. Формат токена и запросов верный,
> это серверная настройка. Нужно попросить техподдержку Linko включить
> External API для аккаунта.

### 4. Канал A — подключение аккаунта

На аккаунте нужен **Telegram Premium**. Затем:
Настройки → **Telegram Business** → **Чат-боты** → указать своего бота → дать право отвечать.

Перед этим обязательно:

- **Исключения.** В том же разделе Business исключить личные чаты владельца.
- **Белый список пилота.** В `.env` перечислить `BUSINESS_ALLOWLIST` — только эти
  чаты бот будет обрабатывать. Пустое значение = все, кого пропустят настройки Business.

## Режимы

Переключаются одной строкой в `.env`. Начинать всегда с `dry_run`.

| Режим | Клиентам | Сотрудникам | Зачем |
|---|---|---|---|
| `dry_run` | нет | нет | всё пишется в лог. Безопасно смотреть, что бот собирался отправить |
| `shadow` | **нет** | да | неделя 4 из ТЗ: карточки ЭСФ уже приходят, клиентам бот молчит |
| `live` | да | да | боевой режим |

В `dry_run` и `shadow` отметка `order_synced` в Linko не ставится — данные не портятся.

### Про список номеров

В файле `НОМЕРА ДЛЯ БОТА.xlsx` — 781 строка. Разбор показал:

- **620 уникальных** номеров нормализуются в `+998XXXXXXXXX`;
- **151 повтор** — часть номеров привязана к нескольким точкам
  (самый частый встречается 24 раза). Это штатный случай: один человек
  отвечает за несколько магазинов, бот будет спрашивать, на какую точку заказ;
- **10 битых** — Excel сохранил их числом и потерял старшие цифры
  (`8999255955` вместо `998999255955`). Восстанавливать наугад нельзя,
  они выгружаются в `.data/phones_problems.txt` на ручную правку;
- `+998000000603` — явная заглушка, тоже в отчёт.

После `npm run sync` тот же скрипт сверит номера с точками в Linko и скажет,
кого из списка в системе нет.

```
src/

  db/
    schema.ts          таблицы
    migrate.ts         создание схемы обычным SQL
    index.ts           подключение: PGlite (тест) или Postgres (бой)
  linko/
    client.ts          HTTP-клиент: авторизация, пагинация, ретраи
    types.ts           типы ответов Linko
    sync.ts            инкрементальная синхронизация по last_tm
  bot/
    index.ts           роутер каналов A и B, команды
    send.ts            единственная точка выхода наружу: режимы + дедупликация
    esf.ts             M1 — карточки ЭСФ, кнопки, сводка
  lib/
    phone.ts           нормализация узбекских номеров
    money.ts           деньги целыми сумами, форматирование
    logger.ts
  scripts/             check, sync-once, seed-demo, import-phones
  dev.ts               локальный запуск (long polling)
```

### Два правила, которые лучше не нарушать

1. **Наружу — только через `send()`** из `src/bot/send.ts`. Там режимы,
   дедупликация по ключу и запись в `outbox`. Прямой `api.sendMessage` в обход
   этой функции ломает и защиту от повторов, и `dry_run`.
2. **Деньги — целыми сумами**, тип `numeric`, никаких `float`.
   `0.1 + 0.2` в сумах превращается в спор с бухгалтерией.

## Модель

Подключается Gemini через обычный REST, без SDK. Ключ берётся на
`aistudio.google.com` → Get API key, карта не нужна.

```
GEMINI_API_KEY=...
GEMINI_MODEL=gemini-2.5-flash-lite
```

Бесплатный тариф — 15 запросов в минуту, 1000 в сутки. Нам нужно 200–350.
`npm run models` покажет, что доступно именно вашему ключу.

> На бесплатном тарифе Google использует данные для улучшения своих продуктов.
> Для тестов на выдуманном каталоге это неважно, но перед боем с реальной
> перепиской нужно перейти на платный тариф.

Модель ничего не знает про товары и цены — она вызывает инструменты
из `src/ai/tools.ts`. Придумать цену или акцию она не может: всё, чего
инструмент не вернул, превращается в «уточню у менеджера».

### Файлы: прайсы, фото, ролики

Клиент просит «скиньте прайс» — бот отправляет файл. Работает и в канале A:
файлы от имени бизнес-аккаунта Telegram слать разрешает, в отличие от кнопок.

1. Скопировать `media.example.json` в `media.json`
2. Положить файлы в папку `media/`
3. `npm run media -- sync`

В `media.json` у каждого файла есть `keywords` — по ним модель понимает,
когда файл уместен: «прайс», «narx», «price», «цены». Ключей вне списка
модель придумать не может.

После первой отправки Telegram возвращает `file_id`, и он сохраняется —
дальше тот же файл уходит мгновенно, без повторной заливки.

Ограничения: 50 МБ на файл, типы `document`, `photo`, `video`, `voice`.

### Три уровня проверки

| | Команда | Что проверяет |
|---|---|---|
| 1 | `npm run chat` | диалог в терминале, видно вызовы инструментов |
| 2 | `npm run eval` | 12 проверок поведения: цены, акции, долги, языки |
| 3 | `MODE=shadow` | живой Telegram, ответ уходит в группу, а не клиенту |

## Тестовая база

По умолчанию `DATABASE_URL=pglite://.data/akm` — настоящий Postgres, встроенный
в процесс, лежит файлом в `.data/`. Ставить ничего не нужно.

Начать с чистого листа: удалить папку `.data` и запустить `npm run seed`.

**Две особенности PGlite, на которые легко наступить:**

1. **Только один процесс за раз.** Пока работает `npm run dev`, команды
   `chat`, `eval` и `seed` не запустятся. Остановите бота и повторите.
2. **Жёсткая остановка портит базу.** Останавливайте бота через Ctrl+C —
   он закроет базу штатно. Если каталог всё же испортился, удалите `.data`
   и выполните `npm run seed`.

Обеих проблем нет на боевом Postgres — это ограничение только встроенной базы.

Для боя — обычная строка `postgres://...` (Neon, Supabase, свой сервер).
Схема одна и та же, менять код не нужно.
